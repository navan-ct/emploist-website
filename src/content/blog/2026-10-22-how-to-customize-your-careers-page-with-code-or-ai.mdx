Your careers page is often the first real look a candidate gets at your company. When it looks like the rest of your website, with the same fonts, colors, and voice, it feels like part of your brand rather than a page from a hiring tool.

Every company on Emploist gets a [careers page that's ready on day one](/#careers-page), with its logo and color. When you want more than that, you can change everything about how it looks by editing its code. That sounds technical, but you don't need to be a developer. This guide shows two ways to do it:

1. [**Edit the code in Emploist.**](#option-1-edit-the-code-in-emploist) Good for small changes, like a new headline or font. You see each change in a live preview as you type.
2. [**Let an AI assistant do it.**](#option-2-let-an-ai-assistant-make-the-changes) Good for bigger changes, like a new section. You download the code, describe what you want in plain words, and upload what the assistant sends back.

## What you can change

Your careers page is built from six files. Each one is a small text file you can open and edit:

| File | What it controls |
| --- | --- |
| `layout.liquid` | The frame around every page: the header, the footer, and what loads on every page, like fonts |
| `jobs.liquid` | The main page, with your introduction and the list of open roles |
| `job.liquid` | A single job's page |
| `apply.liquid` | The application form |
| `applied.liquid` | The thank-you page candidates see after applying |
| `styles.css` | How everything looks: colors, fonts, sizes, and spacing |

The files use three simple languages. **HTML** says what's on the page, like headings and buttons. **CSS** says how it looks. **Liquid** adds placeholders, like `{{ company.name }}`, which Emploist replaces with your company's name, your jobs, and other details when a candidate opens the page.

You can't break your careers page by trying things out:

- Nothing changes for candidates until you click **Save**.
- Emploist checks your code before saving it, and tells you what to fix if something is wrong.
- You can go back to the default design at any time.

To get started, sign in as an admin and open **Careers page** in the sidebar. The **Design** tab has your page's color and its code. If all you need is your brand color, pick it under **Primary color** and you're done. No code needed.

## Option 1: Edit the code in Emploist

### Open the editor

Click **Edit code**. Your page's code is on the left, with a tab for each file and a short note on what the file is for. On the right is a live preview of your careers page, filled with sample jobs.

<Figure
  src={editor}
  alt="Emploist's code editor: file tabs and the code of layout.liquid on the left, and a live preview of the careers page on the right."
  caption="The code editor. The preview on the right updates as you type."
/>

Above the preview, **Go to page** switches between every page candidates can see: the list of jobs, a job, the application form, the thank-you page, a closed job, and "Page not found". Clicking a file's tab also shows the page it controls.

### Change the headline

Click the `jobs.liquid` tab. Line 3 holds the big headline at the top of the page:

```liquid
<h1 class="hero-title">Join {{ company.name }}</h1>
```

Change the word "Join" to "Build what's next at". Leave `{{ company.name }}` as it is: Emploist puts your company's name there. A moment after you stop typing, the preview shows the new headline.

<Figure
  src={editorHeadline}
  alt="The jobs.liquid file in the editor with the headline changed to 'Build what's next at {{ company.name }}', and the preview showing 'Build what's next at Fieldnote Labs'."
  caption="Edit the text between the tags, and the preview follows."
/>

### Use your own font

Changing the font takes two small edits. We'll use Fraunces, a free font from [Google Fonts](https://fonts.google.com).

1. **Load the font.** On Google Fonts, open the font, click **Get font**, then **Get embed code**, and copy the `<link>` line that contains `fonts.googleapis.com/css2`. In `layout.liquid`, paste it on a new line just above the line that contains `stylesheet_url`:

   ```html
   <link rel="stylesheet" href="https://fonts.googleapis.com/css2?family=Fraunces:opsz,wght@9..144,100..900&display=swap">
   ```

2. **Use it.** In `styles.css`, find the line near the top that starts with `--font:`, and put the font's name in quotes at the start of the list, followed by a comma:

   ```css
   --font: "Fraunces", ui-sans-serif, system-ui, -apple-system, "Segoe UI", Roboto,
   ```

   The other fonts in the list are backups, in case a browser can't load yours.

### Fix mistakes before they go live

If a change breaks something, Emploist tells you right away. The file's tab gets a red mark, the preview shows what went wrong instead of the page, and a list under the code says what's wrong and on which line. Click a problem to jump to it. Most problems are a typo or a missing closing tag, and undoing your last change (<kbd>Cmd</kbd>+<kbd>Z</kbd> on a Mac, <kbd>Ctrl</kbd>+<kbd>Z</kbd> on Windows) usually fixes it.

<Figure

You can't save while there are problems, so candidates never see a broken page.

## Option 2: Let an AI assistant make the changes

For bigger changes, like a new section or a different layout, it's often easier to describe what you want and let an AI assistant write the code. We'll use [Claude](https://claude.ai), but any assistant that can read and send back files works in much the same way.

### Download your code

On the **Design** tab, click **Download ZIP**. You'll get a file called `careers-page.zip` with:

- **Your six files**, with any changes you've saved.
- **A guide, `README.md`**, which explains the rules for careers pages and every placeholder you can use. This is what helps an AI assistant get the code right on the first try.
- **A preview kit** (`preview.mjs` and `company.json`) for previewing the page on your computer. It's optional, and we cover it [at the end](#preview-on-your-computer-optional).

You don't need to unzip it: Claude can read the ZIP as it is.

### Ask for the changes

Open [claude.ai](https://claude.ai), start a new chat, and attach `careers-page.zip` with the **+** button. Then describe what you'd like in plain words, as you would to a designer. Here's what we asked:

> Here's the code for our careers page on Emploist. Please make the jobs page feel warmer and more welcoming: a bigger intro with a button to the open roles, and a "Why join us" section with a few benefits (remote-friendly, learning budget, 30 days off, team offsites). Follow README.md and send me back a ZIP I can upload.

### Get the updated code

Claude took about four minutes. It read the guide and the code, made the changes, and then checked its own work: it previewed the page at desktop and phone sizes with the preview kit, and ran the same check Emploist runs before saving. Then it sent back a new `careers-page.zip`, with a summary of what it changed:

- **A bigger, warmer intro**, with a new headline, a welcoming line, and a **See open roles** button that jumps down to the list.
- **A "Why join us" section** with four cards: remote-friendly, learning budget, 30 days off, and team offsites.
- **Small touches to the open roles**, like a short introduction above the list.

<Figure

Read the summary before you upload. Here, Claude mentioned that it replaced our new headline with its own, "Come build what's next with us", and told us which line to edit to change it. It also kept the benefits general, without making up details like the size of the learning budget, so we could add our own.

If the result isn't quite right, keep the conversation going: "make the button green", "add a benefit about health insurance", or "make the intro shorter". Ask for the updated ZIP when you're done.

### Upload it to Emploist

Back on the **Design** tab, click **Upload ZIP** and choose the ZIP from Claude. Emploist opens the editor with the new code loaded, but not saved yet, so you can look before anything changes for candidates.

  caption="The uploaded code opens in the editor, ready to check."

Use **Go to page** and the phone icon to check every page. If something isn't right, fix it in the editor or ask Claude again. When it all looks good, click **Save**.

## Preview on your computer (optional)

If you'd like to try changes on your computer before uploading them, the ZIP's preview kit shows your careers page with sample jobs, just like Emploist's preview. It needs [Node.js](https://nodejs.org) 22 or newer.

1. Unzip `careers-page.zip`.
2. Open a terminal in the unzipped folder and run `node preview.mjs`.
3. Open `http://localhost:4321` in your browser, and reload it after each change.

To check your code for problems the same way Emploist does before saving, run `node preview.mjs check`. If you use an AI assistant that works with files on your computer, such as Claude Code, you can ask it to run these for you.

## Good to know

- **Only admins can edit the code.** Other team members can see the Design tab, but not change it.
- **JavaScript doesn't run on careers pages.** This keeps your page and your candidates safe. Everything in this guide works without it.
- **Images, fonts, and stylesheets can load from other websites**, as long as their addresses start with `https://`. That's how Google Fonts works.
- **Application forms keep working** however you change the design, so applications keep landing in each job's inbox.
